# 用户端观看直播前端接入说明

## 1. 适用范围

本文档用于说明用户端“直播列表 / 直播详情 / 直播播放 / 回放视频”相关接口的前端接入方式。

覆盖内容：

- 用户端登录
- 直播列表接口
- 直播详情接口
- 播放地址字段说明
- 直播状态口径
- 回放视频字段说明
- 页面接入建议

本文档只面向用户端观看直播，不涉及管理端创建直播或 OBS 推流。

## 2. 先说结论

用户端观看直播的主链路是：

```text
用户登录
  ->
GET /api/v1/app/live-sessions 获取直播列表
  ->
GET /api/v1/app/live-sessions/{id} 获取直播详情
  ->
前端根据详情里的 httpFlvUrl / hlsUrl / liveUrl / playbackUrl 播放
```

当前系统里最关键的约定：

- 直播列表和详情当前需要用户端登录态
- 用户端只会看到 `reviewStatus=APPROVED` 且 `liveStatus!=CANCELED` 的直播
- 详情里会同时返回：
  - `liveUrl`
  - `playbackUrl`
  - `httpFlvUrl`
  - `hlsUrl`
- 当前接入时，前端优先用：
  - 直播中：`httpFlvUrl`
  - 回放或兼容场景：`hlsUrl`

## 3. 用户端登录

### 3.1 登录接口

- 方法：`POST`
- 路径：`/api/v1/app/auth/login`
- Content-Type：`application/json`

请求示例：

```json
{
  "username": "td_user_01",
  "password": "User@123456"
}
```

响应关键字段：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "tokenType": "Bearer",
    "accessToken": "xxxxxxxx",
    "expiresIn": 7200,
    "user": {
      "id": 1001,
      "username": "td_user_01",
      "nickname": "杏林新苗",
      "avatarUrl": "/api/v1/files/123/content"
    }
  }
}
```

说明：

- 后续用户端直播接口统一带：

```text
Authorization: Bearer <accessToken>
```

## 4. 用户端直播接口总览

### 4.1 分页查询直播列表

- 方法：`GET`
- 路径：`/api/v1/app/live-sessions`

### 4.2 查询直播详情

- 方法：`GET`
- 路径：`/api/v1/app/live-sessions/{id}`

## 5. 分页查询直播列表

### 5.1 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page` | `number` | 否 | 默认 `1` |
| `size` | `number` | 否 | 默认 `20`，最大 `100` |
| `keyword` | `string` | 否 | 按标题、主播、讲师模糊搜索 |
| `liveStatus` | `number` | 否 | 按直播状态过滤 |

### 5.2 `liveStatus` 枚举

当前接口按数值传输：

| 值 | 含义 |
| --- | --- |
| `0` | 未开始 |
| `1` | 直播中 |
| `2` | 已结束 |
| `3` | 已取消 |

说明：

- 用户端接口本身已经过滤掉 `已取消`
- 前端一般只会用：
  - `0` 未开始
  - `1` 直播中
  - `2` 已结束

### 5.3 列表请求示例

查询全部直播：

```http
GET /api/v1/app/live-sessions?page=1&size=20
Authorization: Bearer <accessToken>
```

只查直播中：

```http
GET /api/v1/app/live-sessions?page=1&size=20&liveStatus=1
Authorization: Bearer <accessToken>
```

### 5.4 列表响应结构

响应包裹结构：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "records": [],
    "total": 0,
    "page": 1,
    "size": 20
  }
}
```

`records[]` 每项字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `number` | 直播 ID |
| `title` | `string` | 直播标题 |
| `coverUrl` | `string` | 封面地址 |
| `anchorName` | `string` | 主播名称 |
| `speakerName` | `string` | 展示讲师名称 |
| `tags` | `string[]` | 标签列表 |
| `liveUrl` | `string` | 直播播放地址 |
| `playbackUrl` | `string` | 回放播放地址 |
| `streamName` | `string` | 流名称 |
| `httpFlvUrl` | `string` | HTTP-FLV 播放地址 |
| `hlsUrl` | `string` | HLS 播放地址 |
| `startAt` | `string` | 开始时间 |
| `endAt` | `string \| null` | 结束时间 |
| `reviewStatus` | `number` | 审核状态 |
| `liveStatus` | `number` | 直播状态 |
| `browseCount` | `number` | 浏览数 |
| `favoriteCount` | `number` | 收藏数 |
| `favorited` | `boolean` | 当前用户是否已收藏 |
| `videos` | `array` | 列表接口当前返回空数组 |

### 5.5 列表页推荐展示字段

推荐至少展示：

- `coverUrl`
- `title`
- `anchorName`
- `speakerName`
- `startAt`
- `liveStatus`
- `browseCount`
- `favoriteCount`

状态文案建议：

| `liveStatus` | 文案 |
| --- | --- |
| `0` | 未开始 |
| `1` | 直播中 |
| `2` | 已结束 |

## 6. 查询直播详情

### 6.1 请求示例

```http
GET /api/v1/app/live-sessions/104
Authorization: Bearer <accessToken>
```

### 6.2 详情返回规则

详情接口只会返回满足以下条件的直播：

- `deleted = 0`
- `reviewStatus = APPROVED`
- `liveStatus != CANCELED`

如果不满足，会返回：

```json
{
  "success": false,
  "code": "NOT_FOUND",
  "message": "Live session does not exist",
  "data": null
}
```

### 6.3 详情响应字段

详情字段与列表一致，但有两个差异：

- `videos` 会返回已启用的回放视频列表
- 互动统计是当前直播的完整统计值

响应结构示例：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "id": 104,
    "title": "test",
    "coverUrl": "",
    "anchorName": "zzz",
    "speakerName": "zzz",
    "tags": [],
    "liveUrl": "https://api-test.arez.cc.cd/live/live-104.flv",
    "playbackUrl": "https://api-test.arez.cc.cd/live/live-104.m3u8",
    "streamName": "live-104",
    "httpFlvUrl": "https://api-test.arez.cc.cd/live/live-104.flv",
    "hlsUrl": "https://api-test.arez.cc.cd/live/live-104.m3u8",
    "startAt": "2026-06-11T22:00:00",
    "endAt": null,
    "reviewStatus": 2,
    "liveStatus": 1,
    "browseCount": 0,
    "favoriteCount": 0,
    "favorited": false,
    "videos": []
  }
}
```

## 7. 播放地址字段怎么用

详情里会返回 4 个和播放有关的字段：

| 字段 | 含义 | 推荐用途 |
| --- | --- | --- |
| `liveUrl` | 直播主播放地址 | 一般可直接用于直播播放 |
| `playbackUrl` | 回放主播放地址 | 一般可直接用于回放播放 |
| `httpFlvUrl` | HTTP-FLV 地址 | 直播中优先用，延迟更低 |
| `hlsUrl` | HLS 地址 | 兼容性更高，适合 H5 播放 |

当前后端生成逻辑是：

- `liveUrl` 默认等于 `httpFlvUrl`
- `playbackUrl` 默认等于 `hlsUrl`

所以前端可以按这个策略：

### 7.1 直播中播放

优先：

```text
httpFlvUrl
```

如果播放器不支持 FLV，则降级：

```text
hlsUrl
```

### 7.2 已结束或回放场景

优先：

```text
hlsUrl
```

### 7.3 最简化策略

如果前端不想做太多分支，可以直接用：

- 直播中：`liveUrl`
- 回放：`playbackUrl`

## 8. 回放视频 `videos`

详情里的 `videos` 是直播下挂载的回放视频列表，只返回已启用的视频。

每项字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `number` | 视频 ID |
| `liveSessionId` | `number` | 所属直播 ID |
| `title` | `string` | 视频标题 |
| `videoUrl` | `string` | 回放视频地址 |
| `durationSeconds` | `number \| null` | 时长秒数 |
| `sortOrder` | `number \| null` | 排序值 |
| `status` | `number` | 启用状态，`1` 为启用 |

说明：

- 如果 `videos` 为空，不表示接口异常，只表示该直播还没挂载独立回放视频
- 这时前端可以继续使用直播主记录上的 `playbackUrl`

## 9. 审核状态与直播状态口径

### 9.1 `reviewStatus`

当前按数值返回：

| 值 | 含义 |
| --- | --- |
| `0` | 草稿 |
| `1` | 待审核 |
| `2` | 审核通过 |
| `3` | 审核拒绝 |

用户端正常只会看到：

```text
2
```

### 9.2 `liveStatus`

当前按数值返回：

| 值 | 含义 |
| --- | --- |
| `0` | 未开始 |
| `1` | 直播中 |
| `2` | 已结束 |
| `3` | 已取消 |

用户端页面建议：

- `0`：展示“预告 / 即将开始”
- `1`：展示“直播中”
- `2`：展示“可回看”或“已结束”

## 10. 页面接入建议

### 10.1 列表页

推荐分 3 个 Tab：

- 全部
- 直播中
- 已结束

对应请求：

```text
全部: 不传 liveStatus
直播中: liveStatus=1
已结束: liveStatus=2
```

### 10.2 详情页

推荐展示：

- 封面
- 标题
- 主播 / 讲师
- 标签
- 开始时间
- 状态
- 浏览数
- 收藏数
- 播放器
- 回放视频列表

### 10.3 播放器选型建议

如果是 Web H5：

- FLV 播放：`flv.js`
- HLS 播放：`hls.js`

建议策略：

- 直播中先尝试 `httpFlvUrl`
- 如果播放器或浏览器不支持，再切 `hlsUrl`

## 11. 常见问题

### 11.1 为什么列表里有直播，详情却查不到

可能原因：

- 直播刚被取消
- 直播已被删除
- 当前直播不满足用户端可见条件

### 11.2 为什么详情里 `videos` 为空

原因：

- 还没有挂回放视频
- 回放视频未启用

处理：

- 先用主记录的 `playbackUrl`

### 11.3 为什么播放地址返回 404

这通常不是前端路由问题，而是直播流当前不存在。

常见原因：

- 主播还没开始推流
- 推流已经断开
- 当前没有生成对应的 HLS 切片

前端处理建议：

- 直播中优先尝试 `httpFlvUrl`
- 失败时提示“直播流暂未就绪，请稍后重试”

## 12. 一套最小接入流程

1. 用户登录，拿 `accessToken`
2. 调 `GET /api/v1/app/live-sessions?page=1&size=20`
3. 用户点击某条直播
4. 调 `GET /api/v1/app/live-sessions/{id}`
5. 根据 `liveStatus` 选择播放地址：
   - `1`：优先 `httpFlvUrl`
   - `2`：优先 `hlsUrl` 或 `playbackUrl`
6. 如果有 `videos`，在详情页展示回放列表
