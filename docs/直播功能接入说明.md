# 直播功能接入说明

本文档说明当前仓库中直播模块的管理端能力、用户端展示字段和 SRS 对接方式，供前后端联调和运营配置使用。

## 1. 基础约定

- 管理端接口前缀：`/api/v1/admin/live-sessions`
- 用户端接口前缀：`/api/v1/app/live-sessions`
- SRS 回调接口：`POST /api/v1/integrations/srs/live-hooks`
- 认证方式：管理端接口使用 `Authorization: Bearer <token>`，SRS 回调不走登录态
- 直播流定位字段：`streamName`

## 2. 管理端能力

### 2.1 新增和修改直播

管理端当前可维护以下核心字段：

- `title`：直播标题
- `coverUrl`：直播封面
- `tags`：直播标签
- `anchorName`：讲师/主播名
- `speakerName`：展示用讲师名
- `streamName`：直播流名，用于 SRS 推流和回调定位
- `liveUrl`：推流地址
- `playbackUrl`：拉流地址
- `reviewStatus`：审核状态
- `liveStatus`：直播状态
- `startAt` / `endAt`：直播时间

对应接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/admin/live-sessions` | 新增直播 |
| PUT | `/api/v1/admin/live-sessions/{id}` | 修改直播 |
| GET | `/api/v1/admin/live-sessions/{id}` | 查询直播详情 |
| GET | `/api/v1/admin/live-sessions/{id}/streaming` | 查询直播流配置 |

### 2.2 删除直播

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| DELETE | `/api/v1/admin/live-sessions/{id}` | 删除单个直播 |
| POST | `/api/v1/admin/live-sessions/batch-delete` | 批量删除直播 |

批量删除请求体复用 `IdListRequest`：

```json
{
  "ids": [1, 2, 3]
}
```

### 2.3 审核直播

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| PATCH | `/api/v1/admin/live-sessions/{id}/review` | 审核直播 |

审核状态映射如下：

| reviewStatus | 对外含义 |
| --- | --- |
| `PENDING` | 审核中 |
| `APPROVED` | 已发布 |
| `REJECTED` | 审核未通过 |

说明：

- 审核通过后，直播可被视为已发布内容。
- 审核拒绝时，后端会同步调整直播状态，避免前端继续显示为可播状态。

## 3. SRS 对接

### 3.1 运行时配置

直播相关配置位于 `app.live`：

- `app.live.enabled`
- `app.live.media-host`
- `app.live.publish-host`
- `app.live.playback-host`
- `app.live.playback-scheme`
- `app.live.rtmp-port`
- `app.live.http-port`
- `app.live.app-name`
- `app.live.callback-base-url`
- `app.live.callback-path`
- `app.live.callback-token`

### 3.2 推拉流地址

系统会根据 `streamName` 生成或返回直播流相关地址，管理端在“直播流配置”接口中可直接拿到：

- `publishUrl`
- `httpFlvUrl`
- `hlsUrl`
- `callbackUrl`

`callbackUrl` 就是 SRS 回调需要访问的地址。

### 3.3 回调行为

当前支持的 SRS 回调动作：

- `on_publish`：推流开始，后端把直播状态更新为 `LIVE`
- `on_unpublish`：推流结束，后端把直播状态更新为 `ENDED`

回调请求会按 `streamName` 反查直播，因此 `streamName` 必须唯一且稳定。

### 3.4 测试环境部署

当前仓库的 `compose.test.yml` 已补齐一套最小可用的 SRS 部署，遵循 SRS 官方 getting started 文档里的直播场景端口约定：

- `1935`：RTMP 推流
- `1985`：SRS HTTP API
- `8080`：HTTP-FLV / HLS 播放

测试环境 compose 新增了 `srs` service，并挂载以下文件：

- `docker/srs/srs.template.conf`
- `docker/srs/start-srs.sh`

其中：

- `on_publish` / `on_unpublish` 已指向后端回调 `POST /api/v1/integrations/srs/live-hooks`
- 默认回调基础地址使用容器内 `http://app:8080`，避免 SRS 再绕公网域名回调自己
- 如需启用回调鉴权，保持 `APP_LIVE_CALLBACK_TOKEN` 与 SRS 容器环境一致即可

建议的测试环境变量：

- `APP_LIVE_MEDIA_HOST`：填写测试域名或服务器公网 IP，供后端生成 RTMP/HTTP-FLV/HLS 地址
- `APP_LIVE_PUBLISH_HOST`：OBS/FFmpeg 实际推流要访问的主机名，默认回退 `APP_LIVE_MEDIA_HOST`
- `APP_LIVE_PLAYBACK_HOST`：前端页面或播放器实际播放要访问的主机名，默认回退 `APP_LIVE_MEDIA_HOST`
- `APP_LIVE_PLAYBACK_SCHEME`：播放协议，HTTP 环境填 `http`，HTTPS 页面联调建议填 `https`
- `APP_LIVE_RTMP_PORT=1935`
- `APP_LIVE_HTTP_PORT=8080`
- `SRS_RTMP_BIND_HOST=0.0.0.0`
- `SRS_HTTP_BIND_HOST=0.0.0.0`
- `SRS_API_BIND_HOST=127.0.0.1`

如果后续要接 WebRTC，再按 SRS 官方文档继续追加 `8000/udp` 等端口和相应配置；当前仓库这次只补了 RTMP 推流、HTTP-FLV/HLS 播放和状态回调所需的最小集合。

## 4. 实操验收

### 4.1 脚本化冒烟

仓库已提供直播冒烟脚本：

```bash
./scripts/live-smoke.sh
```

如果后端不在默认 `8080`，可显式覆盖：

```bash
BASE_URL=http://127.0.0.1:18080 ./scripts/live-smoke.sh
```

脚本会完成以下检查：

1. 管理端登录
2. 创建直播
3. 审核直播
4. 查询直播流配置
5. 用户端登录并查询直播详情
6. 模拟 SRS `on_publish`
7. 校验直播状态切换为 `LIVE`
8. 模拟 SRS `on_unpublish`
9. 校验直播状态切换为 `ENDED`

### 4.2 OBS 推流

先调用：

```text
GET /api/v1/admin/live-sessions/{id}/streaming
```

返回值中重点关注：

- `publishUrl`
- `streamName`
- `httpFlvUrl`
- `hlsUrl`

OBS 填写方式：

- Server：取 `publishUrl` 去掉最后的 `/streamName`
- Stream Key：取 `streamName`

例如当前本地实跑结果：

```text
publishUrl = rtmp://127.0.0.1:1935/live/smoke-20260607-190443
Server     = rtmp://127.0.0.1:1935/live
Stream Key = smoke-20260607-190443
```

### 4.3 播放验证

直播推流开始后，可优先验证两个播放地址：

- HTTP-FLV：`httpFlvUrl`
- HLS：`hlsUrl`

如果你还不确定是“业务前端播放器”问题还是“直播链路”问题，可以先直接打开仓库内置的本地调试页：

```text
/debug/live.html
```

调试页支持两种模式：

- `HLS`
- `HTTP-FLV`

把 `streaming` 接口或用户端直播详情返回的 `hlsUrl` / `httpFlvUrl` 粘进去即可直接测试播放，不需要先接入你自己的前端页面。

当前本地最小媒体层验证已经跑通过一次，使用独立 SRS 测试容器加 `ffmpeg` 推流拿到以下证据：

- SRS HTTP API：`GET http://127.0.0.1:1985/api/v1/versions` 返回 `5.0.213`
- `ffmpeg` 成功推流到 `rtmp://127.0.0.1:1935/live/smoke-media-test`
- `GET http://127.0.0.1:8080/live/smoke-media-test.m3u8` 返回有效 HLS 清单
- SRS 日志显示 `GET /live/smoke-media-test.flv` 已创建 FLV consumer

这说明当前仓库的最小 RTMP -> HTTP-FLV/HLS 媒体链路已经具备运行证据。

### 4.4 排错顺序

如果前端看不到直播，按这个顺序查：

1. 管理端 `streaming` 接口是否能返回 `publishUrl/httpFlvUrl/hlsUrl`
2. SRS `GET /api/v1/versions` 是否正常
3. SRS `GET /api/v1/streams/` 是否能看到对应流
4. `POST /api/v1/integrations/srs/live-hooks` 的 `on_publish` 是否把直播状态改成 `LIVE`
5. 浏览器直接访问 `hlsUrl`
6. 如 HLS 正常而前端仍不播，再检查前端播放器实现

## 5. 管理端推荐流程

1. 新增直播时填写标题、封面、标签、讲师、推流地址、拉流地址、状态和时间。
2. 保存后由运营人员发起审核。
3. 审核通过后，前端根据 `reviewStatus=APPROVED` 视为已发布。
4. 直播开播和结束由 SRS 回调同步更新状态。
5. 直播下线时可使用单删或批量删除清理数据。

## 6. 联调注意事项

- `streamName` 留空时后端会自动生成，但上线前建议固定配置。
- `liveUrl` 和 `playbackUrl` 是业务字段，不等同于 SRS 回调地址。
- 用户端现在还会额外返回 `streamName`、`httpFlvUrl`、`hlsUrl`，前端不要继续只依赖手填 `liveUrl` / `playbackUrl`。
- 前端不要把 `reviewStatus` 和 `liveStatus` 混用，前者是审核流，后者是直播运行态。
- 用户端直播列表和详情会返回浏览量、收藏量和当前用户收藏态。
