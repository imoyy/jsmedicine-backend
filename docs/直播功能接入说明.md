# 直播功能接入说明

本文档覆盖以下三个场景的完整操作流程：

- **运营人员**：管理端创建/审核/管理直播
- **主播**：OBS 推流到 SRS
- **用户**：观看直播/回放

## 1. 系统架构

```
OBS (RTMP推流) ──→ SRS (流媒体服务器) ──→ HTTP-FLV / HLS 播放
                       │
                       └── on_publish / on_unpublish 回调
                                │
                                ↓
                       Spring Boot 后端 (更新 liveStatus)
```

- 推流协议：RTMP（端口 1935）
- 播放协议：HTTP-FLV（低延迟）/ HLS（高兼容）
- 状态同步：SRS webhook 回调后端的 `POST /api/v1/integrations/srs/live-hooks`

## 2. 环境变量与部署检查

### 2.1 确认 .env.test 配置

在部署服务器（`/root/jsmedicine-test`）上检查 `.env.test`：

```bash
grep -E '^APP_LIVE_|^SRS_' /root/jsmedicine-test/.env.test
```

必须配置项示例（以 `api-test.arez.cc.cd` 为例）：

```ini
APP_LIVE_ENABLED=true
APP_LIVE_MEDIA_HOST=api-test.arez.cc.cd
APP_LIVE_PUBLISH_HOST=api-test.arez.cc.cd
APP_LIVE_PLAYBACK_HOST=api-test.arez.cc.cd
APP_LIVE_PLAYBACK_BASE_URL=https://api-test.arez.cc.cd/live
APP_LIVE_PLAYBACK_SCHEME=https
APP_LIVE_RTMP_PORT=1935
APP_LIVE_HTTP_PORT=8080
APP_LIVE_APP_NAME=live
APP_LIVE_CALLBACK_BASE_URL=http://app:8080
APP_LIVE_CALLBACK_TOKEN=your-secret-token-here   # 建议设一个值

SRS_CALLBACK_BASE_URL=http://app:8080/api/v1/integrations/srs/live-hooks
```

`CALLBACK_TOKEN` 可选但推荐 — 如果设了，SRS 回调会带 `?token=xxx`，后端校验合法性。

### 2.2 确认 SRS 容器运行

```bash
docker compose -f compose.test.yml ps srs
curl -s http://127.0.0.1:1985/api/v1/versions | python3 -m json.tool
```

### 2.3 确认回调链路

```bash
docker exec jsmedicine-test-srs cat /usr/local/srs/conf/docker-live.conf | grep -A2 http_hooks
```

期望输出：

```
http_hooks {
    enabled         on;
    on_publish      http://app:8080/api/v1/integrations/srs/live-hooks?token=...;
    on_unpublish    http://app:8080/api/v1/integrations/srs/live-hooks?token=...;
}
```

如果改了 `.env.test`，需要重启容器生效：

```bash
docker compose -f compose.test.yml up -d app srs
```

## 3. OBS 推流配置

### 3.1 获取推流地址

通过管理端创建直播并审核通过后，调用「直播流配置」接口拿到推流地址：

```bash
curl -s "https://api-test.arez.cc.cd/api/v1/admin/live-sessions/{liveId}/streaming" \
  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool
```

返回关键字段：

```json
{
  "publishUrl": "rtmp://api-test.arez.cc.cd:1935/live/live-101",
  "streamName": "live-101",
  "httpFlvUrl": "https://api-test.arez.cc.cd/live/live-101.flv",
  "hlsUrl": "https://api-test.arez.cc.cd/live/live-101.m3u8"
}
```

### 3.2 OBS 设置

打开 OBS Studio → **设置 → 推流**：

| 字段 | 值 | 说明 |
|------|-----|------|
| 服务 | `自定义` | |
| 服务器 | `rtmp://api-test.arez.cc.cd:1935/live` | `publishUrl` 去掉末尾的 `/{streamName}` |
| 推流密钥 | `live-101` | `streamName` 的值 |

> `publishUrl` 完整格式是 `rtmp://host:1935/live/{streamName}`，OBS 里「服务器」填 `rtmp://host:1935/live`，「推流密钥」填 `{streamName}`。

### 3.3 添加直播源

点「来源」左下角 `+` → 选择「显示器采集」/「窗口采集」/「媒体源」→ 按需调整画面 → 点「开始推流」。

### 3.4 验证推流成功

OBS 状态栏显示绿色「正在推流」。同时验证后端状态已变更：

```bash
curl -s "https://api-test.arez.cc.cd/api/v1/admin/live-sessions/{liveId}" \
  -H "Authorization: Bearer $TOKEN" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['liveStatus'])"
```

输出应为 `LIVE`。

## 4. 观看直播

### 方式一：HTTP-FLV（低延迟）

SRS 直出地址：

```
https://api-test.arez.cc.cd/live/live-101.flv
```

网页播放可用 flv.js，桌面可用 VLC → 媒体 → 打开网络串流。

### 方式二：HLS（浏览器原生友好）

```
https://api-test.arez.cc.cd/live/live-101.m3u8
```

H5 `<video>` 标签 + hls.js 即可播放。

### 方式三：用户端接口

```bash
# 列表（只看已审核 + 未取消的直播）
curl -s "https://api-test.arez.cc.cd/api/v1/app/live-sessions" | python3 -m json.tool

# 详情（含 httpFlvUrl / hlsUrl / 互动统计）
curl -s "https://api-test.arez.cc.cd/api/v1/app/live-sessions/{liveId}" | python3 -m json.tool
```

> ⚠️ HTTPS 页面加载 HTTP 资源的限制：当前 SRS 的 HTTP 端口是 8080 且无 HTTPS 证书。
> 开发联调阶段可以在浏览器中允许混合内容，或使用 VLC 直接拉流。
> 生产上线时需为 SRS 的 HTTP 端口配 HTTPS 证书，或通过 nginx 反向代理加 SSL。

## 5. 完整操作流程（管理端）

### 5.1 管理员登录

```bash
curl -s -X POST https://api-test.arez.cc.cd/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"td_admin","password":"Admin@123456"}' | python3 -m json.tool

TOKEN="<返回的 data.token>"
```

### 5.2 创建直播

```bash
curl -s -X POST https://api-test.arez.cc.cd/api/v1/admin/live-sessions \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "今日直播：中医理论基础",
    "anchorName": "陈景岐",
    "speakerName": "陈景岐",
    "startAt": "2026-06-11T20:00:00",
    "endAt": "2026-06-11T22:00:00",
    "reviewStatus": "APPROVED",
    "liveStatus": "NOT_STARTED"
  }' | python3 -m json.tool
```

> `reviewStatus` 可直接设为 `APPROVED` 跳过审核步骤；如需审核流程则设为 `PENDING`，然后调用审核接口。

### 5.3 审核（如创建时未直接 APPROVED）

```bash
curl -s -X PATCH "https://api-test.arez.cc.cd/api/v1/admin/live-sessions/{liveId}/review" \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"reviewStatus": "APPROVED", "comment": "审核通过"}' | python3 -m json.tool
```

### 5.4 OBS 推流 → SRS 回调 → liveStatus 变为 LIVE

OBS 开始推流后自动完成，无需人工调接口。

### 5.5 OBS 停止推流 → liveStatus 变为 ENDED

OBS 停止推流后自动完成。

### 5.6 添加回放视频（可选）

直播结束后，在直播下挂载点播回放视频：

```bash
curl -s -X POST https://api-test.arez.cc.cd/api/v1/admin/live-sessions/videos \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "liveSessionId": {liveId},
    "title": "今日直播回放",
    "videoUrl": "https://your-storage/replay.mp4",
    "durationSeconds": 7200,
    "sortOrder": 1
  }' | python3 -m json.tool
```

### 5.7 删除直播

```bash
# 单删
curl -s -X DELETE "https://api-test.arez.cc.cd/api/v1/admin/live-sessions/{liveId}" \
  -H "Authorization: Bearer $TOKEN"

# 批量删除
curl -s -X POST "https://api-test.arez.cc.cd/api/v1/admin/live-sessions/batch-delete" \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"ids": [1, 2, 3]}'
```

把 Token 填好，直接粘贴到终端运行：

```bash

LIVE_ID=$(curl -s -X POST https://api-test.arez.cc.cd/api/v1/admin/live-sessions \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{
    \"title\": \"测试直播 $(date +%H:%M)\",
    \"anchorName\": \"测试主播\",
    \"speakerName\": \"测试主讲\",
    \"streamName\": \"$STREAM_NAME\",
    \"startAt\": \"$(date -Iseconds -d '+1 hour')\",
    \"endAt\": \"$(date -Iseconds -d '+3 hours')\",
    \"reviewStatus\": \"APPROVED\",
    \"liveStatus\": \"NOT_STARTED\"
  }" | python3 -c "import sys,json;print(json.load(sys.stdin)['data']['id'])")

echo "OBS 推流密钥: $STREAM_NAME"

  -H "Authorization: Bearer $TOKEN" | python3 -m json.tool
```

## 7. 接口参考

### 7.1 管理端

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/v1/admin/live-sessions` | `live:view` | 分页查询（支持 keyword / reviewStatus / liveStatus） |
| GET | `/api/v1/admin/live-sessions/{id}` | `live:view` | 直播详情 |
| GET | `/api/v1/admin/live-sessions/{id}/streaming` | `live:view` | 直播流配置（推拉流地址） |
| GET | `/api/v1/admin/live-sessions/{liveSessionId}/videos` | `live:view` | 分页查询回放视频 |
| POST | `/api/v1/admin/live-sessions` | `live:edit` | 新增直播 |
| PUT | `/api/v1/admin/live-sessions/{id}` | `live:edit` | 修改直播 |
| POST | `/api/v1/admin/live-sessions/videos` | `live:edit` | 新增回放视频 |
| PUT | `/api/v1/admin/live-sessions/videos/{id}` | `live:edit` | 修改回放视频 |
| PATCH | `/api/v1/admin/live-sessions/{id}/review` | `live:review` | 审核（APPROVED / REJECTED） |
| DELETE | `/api/v1/admin/live-sessions/{id}` | `live:edit` | 删除直播（级联删除视频+标签） |
| POST | `/api/v1/admin/live-sessions/batch-delete` | `live:edit` | 批量删除 |
| DELETE | `/api/v1/admin/live-sessions/videos/{id}` | `live:edit` | 删除回放视频 |

### 7.2 用户端

| 方法 | 路径 | 登录 | 说明 |
|------|------|------|------|
| GET | `/api/v1/app/live-sessions` | 可选 | 分页（仅 APPROVED + 未 CANCELED） |
| GET | `/api/v1/app/live-sessions/{id}` | 可选 | 详情（含播放地址+视频+互动统计） |

### 7.3 SRS 回调

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/integrations/srs/live-hooks?token=xxx` | 接收 SRS on_publish / on_unpublish |

### 7.4 直播创建/修改请求体

```json
{
  "title": "直播标题",
  "coverUrl": "/api/v1/files/109/content",
  "anchorName": "主播名",
  "speakerName": "展示讲师名",
  "streamName": "自定义流名（留空自动生成）",
  "tags": ["中医", "针灸"],
  "liveUrl": null,
  "playbackUrl": null,
  "startAt": "2026-06-11T20:00:00",
  "endAt": "2026-06-11T22:00:00",
  "reviewStatus": "PENDING",
  "liveStatus": "NOT_STARTED"
}
```

### 7.5 状态枚举

**ReviewStatus（审核状态）**：

| 值 | 含义 |
|----|------|
| `PENDING` | 待审核 |
| `APPROVED` | 已发布（用户端可见） |
| `REJECTED` | 已拒绝，SRS 会拒绝推流 |

**LiveStatus（直播状态）**：

| 值 | 含义 | 触发方式 |
|----|------|---------|
| `NOT_STARTED` | 未开始 | 创建时默认 |
| `LIVE` | 直播中 | SRS on_publish 回调 |
| `ENDED` | 已结束 | SRS on_unpublish 回调 |
| `CANCELED` | 已取消 | 审核拒绝时自动设置 |

## 8. 联调注意事项

- `streamName` 在全表唯一，留空时后端自动生成 `live-{id}`。
- `liveUrl` / `playbackUrl` 是可选覆盖字段，不填时后端根据 `streamName` + 配置自动计算。
- 前端不要混用 `reviewStatus`（审核流）和 `liveStatus`（推流运行态）。
- 用户端列表/详情返回 `browseCount`（浏览数）、`favoriteCount`（收藏数）、`favorited`（当前用户是否已收藏）。
- 用户端只有在 `reviewStatus=APPROVED` 且 `liveStatus!=CANCELED` 时才能看到该直播。
- 审核拒绝时后端自动将 `liveStatus` 设为 `CANCELED`。
- SRS 回调通过 `streamName` 反查直播，推流前必须确认 `streamName` 存在于 `live_sessions`。
