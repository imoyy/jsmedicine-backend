# 管理端专家认证审核前端接入说明

## 1. 适用范围

本文档用于说明管理端“专家认证审核”页面的前端接入方式。

当前后端已提供：

- 专家认证申请分页列表
- 专家认证申请详情
- 专家认证审核

审核通过后的后端行为：

1. 自动生成或同步 `experts` 专家档案
2. 自动替换专家分类关系
3. 自动激活当前用户的 `EXPERT` 身份
4. 默认保留 `consultEnabled=DISABLED`

说明：

- “审核通过”只代表认证通过。
- 不代表自动进入“可咨询专家”列表。
- 如果业务需要用户马上进入专家工作台，管理端还要继续把专家档案里的 `consultEnabled` 开启。

## 2. 接口总览

前置条件：

- 需要先调用 `POST /api/v1/auth/login` 完成管理端登录。
- 后续请求统一带 `Authorization: Bearer <accessToken>`。

### 2.1 分页查询专家认证申请

- 方法：`GET`
- 路径：`/api/v1/admin/experts/certifications`
- 权限：`expert:certification:view`

### 2.2 查询专家认证申请详情

- 方法：`GET`
- 路径：`/api/v1/admin/experts/certifications/{id}`
- 权限：`expert:certification:view`

### 2.3 审核专家认证申请

- 方法：`PATCH`
- 路径：`/api/v1/admin/experts/certifications/{id}/review`
- 权限：`expert:certification:review`
- Content-Type：`application/json`

## 3. 页面接入流程

### 3.1 流程图

```text
进入专家认证审核页
  ->
GET /api/v1/admin/experts/certifications
  ->
查看某条申请详情
  ->
GET /api/v1/admin/experts/certifications/{id}
  ->
点击“通过”或“驳回”
  ->
PATCH /api/v1/admin/experts/certifications/{id}/review
  ->
刷新详情 / 列表

如果通过后还要开放专家工作台
  ->
继续进入专家管理
  ->
把该专家的 consultEnabled 改为 ENABLED
```

### 3.2 推荐列表筛选项

- 关键字 `keyword`
- 审核状态 `certificationStatus`
- 分页 `page`
- 每页条数 `size`
- 排序 `sort`

推荐 UI：

```text
[关键字搜索框] [状态筛选] [查询]

列表字段：
- 姓名
- 手机号
- 所属机构
- 擅长方向
- 当前状态
- 提交时间
- 审核时间
- 操作：查看 / 通过 / 驳回
```

## 4. 列表接口

### 4.1 请求参数

```http
GET /api/v1/admin/experts/certifications?page=1&size=20&keyword=张&certificationStatus=1
Authorization: Bearer <accessToken>
```

参数说明：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page` | `number` | 否 | 页码，默认 `1` |
| `size` | `number` | 否 | 每页条数，默认 `20` |
| `sort` | `string` | 否 | 当前支持 `submittedAtAsc`；不传时按提交时间倒序 |
| `keyword` | `string` | 否 | 会匹配姓名、手机号、机构、擅长方向 |
| `certificationStatus` | `number` | 否 | 状态筛选 |

状态值：

| 值 | 含义 |
| --- | --- |
| `0` | `UNSUBMITTED` 未提交 |
| `1` | `PENDING` 审核中 |
| `2` | `APPROVED` 已通过 |
| `3` | `REJECTED` 已驳回 |

列表页建议至少展示：

## 5. 详情接口

### 5.1 请求

```http
GET /api/v1/admin/experts/certifications/5
Authorization: Bearer <accessToken>
```

### 5.2 详情页建议展示项

- 基础资料：
  `realName`、`gender`、`birthDate`、`mobile`
- 专业资料：
  `title`、`organization`、`practiceTypeId`、`specialty`
- 展示资料：
  `introduction`、`consultationNotice`
- 分类：
  `categoryIds`
- 材料：
  `certificationFiles`
- 审核信息：
  `certificationStatus`、`certificationSubmittedAt`、`certificationReviewedAt`、`certificationReviewedBy`、`rejectReason`

当前详情接口直接返回 `categoryIds`，不额外返回分类名称。

前端如果要回显分类名，建议：

1. 先调用 `GET /api/v1/admin/experts/categories`
2. 本地建立 `id -> categoryName` 映射
3. 再把 `categoryIds` 转成名称数组展示

## 6. 审核接口

### 6.1 请求体

通过示例：

```json
{
  "certificationStatus": 2,
  "rejectReason": null
}
```

驳回示例：

```json
{
  "certificationStatus": 3,
  "rejectReason": "执业证书图片不清晰，请补充清晰版。"
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `certificationStatus` | `number` | 是 | 只允许 `2=APPROVED` 或 `3=REJECTED` |
| `rejectReason` | `string` | 否 | 驳回原因，最长 512 字符 |

规则：

- 后端只接受 `APPROVED` 和 `REJECTED`
- 通过时会自动清空 `rejectReason`
- 驳回时建议前端强制填写 `rejectReason`

### 6.2 请求示例

```http
PATCH /api/v1/admin/experts/certifications/5/review
Authorization: Bearer <accessToken>
Content-Type: application/json
```

```json
{
  "certificationStatus": 2
}
```

### 6.3 响应结果

审核成功后，接口会返回最新详情结构。

通过后重点结果：

- `certificationStatus = 2`
- `certificationReviewedAt` 有值
- `certificationReviewedBy` 有值
- `rejectReason = null`

驳回后重点结果：

- `certificationStatus = 3`
- `certificationReviewedAt` 有值
- `certificationReviewedBy` 有值
- `rejectReason` 为后端保存的驳回原因

## 7. 审核通过后的业务影响

审核通过后，后端会自动：

1. 按申请资料新建或更新 `experts` 专家档案
2. 替换该专家的分类关系
3. 激活用户 `EXPERT` 身份

但不会自动：

1. 把该专家加入“可咨询专家列表”
2. 自动开启专家工作台接诊能力

原因：

- 后端默认保留 `consultEnabled=DISABLED`
- 这样可以把“认证通过”和“开放接诊”拆成两个独立动作

如果业务要求专家审核通过后立刻能接诊，管理端还需要继续调用专家编辑接口，把：

```text
consultEnabled = ENABLED
```

## 8. 常见失败场景

### 8.1 权限不足

```json
{
  "success": false,
  "code": "FORBIDDEN",
  "message": "Forbidden"
}
```

排查方向：

- 当前管理员是否有 `expert:certification:view`
- 当前管理员是否有 `expert:certification:review`

### 8.2 审核状态非法

例如误传 `PENDING=1`：

```json
{
  "success": false,
  "code": "BAD_REQUEST",
  "message": "Certification review status must be approved or rejected"
}
```

### 8.3 申请不存在

```json
{
  "success": false,
  "code": "NOT_FOUND",
  "message": "Expert certification does not exist"
}
```

## 9. 联调建议

推荐联调顺序：

1. 用户端先提交一条专家认证申请
2. 管理端列表页确认能查到 `PENDING` 申请
3. 管理端详情页检查分类和材料回显
4. 先做一次驳回，确认用户端能看到 `rejectReason`
5. 用户端重新提交
6. 管理端审核通过
7. 用户端调用 `/api/v1/app/auth/me`，确认 `identities` 包含 `EXPERT`
8. 管理端继续开启该专家 `consultEnabled`
9. 用户端确认专家工作台入口恢复

## 10. 页面实现建议

### 10.1 列表页操作建议

- `PENDING`：显示 `通过`、`驳回`
- `APPROVED`：显示 `查看`
- `REJECTED`：显示 `查看`

### 10.2 驳回弹窗建议

```text
标题：驳回专家认证

输入框：
  驳回原因

按钮：
  取消
  确认驳回
```

建议：

- 前端在驳回时强制填写原因
- 通过时不要求填写备注

### 10.3 审核通过后的后台提醒建议

```text
认证已通过。
当前专家身份已激活，但尚未开启接诊。
如需该用户立即进入专家工作台，请继续在专家管理中开启“可接诊”。
```
