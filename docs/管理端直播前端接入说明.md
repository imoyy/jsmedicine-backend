# 管理端直播前端接入说明

## 1. 适用范围

本文档用于说明管理端“直播管理”模块的前端接入方式，覆盖以下内容：

- 管理端登录
- 直播封面上传
- 新建直播
- 修改直播
- 审核直播
- 获取 OBS 推流配置
- 查询直播详情与状态
- 直播回放视频管理
- 删除直播

本文档面向前端页面开发和联调，不涉及服务器部署。

## 2. 先说结论

管理端创建直播的完整链路是：

```text
管理员登录
  ->
如需封面，先走封面三段式上传
  ->
POST /api/v1/admin/live-sessions 新建直播
  ->
如果不是直接发布，PATCH /api/v1/admin/live-sessions/{id}/review 审核
  ->
GET /api/v1/admin/live-sessions/{id}/streaming 获取 OBS 推流配置
  ->
主播在 OBS 中开始推流
  ->
SRS 回调后端，liveStatus 自动从未开始变为直播中
  ->
直播结束后，可新增回放视频
```

前端最容易踩错的点有 4 个：

- `coverUrl` 不能手填外链，必须来自封面上传确认接口返回的稳定地址。
- `reviewStatus` 和 `liveStatus` 当前按数值枚举传，不要传 `APPROVED`、`LIVE` 这种文本。
- `streamName` 必须唯一；不传时后端会自动生成。
- `endAt` 如果传了，必须晚于 `startAt`。

## 3. 认证与权限

### 3.1 登录接口

- 方法：`POST`
- 路径：`/api/v1/auth/login`
- Content-Type：`application/json`

请求示例：

```json
{
  "username": "td_admin",
  "password": "Admin@123456"
}
```

响应关键字段：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "tokenType": "Bearer",
    "accessToken": "xxxxxxxx",
    "expiresIn": 7200,
    "admin": {
      "id": 1,
      "username": "td_admin",
      "realName": "测试管理员"
    },
    "permissions": [
      "live:view",
      "live:edit",
      "live:review"
    ]
  }
}
```

说明：

- 后续直播管理接口统一带 `Authorization: Bearer <accessToken>`。
- 直播相关权限分为：
  - `live:view`
  - `live:edit`
  - `live:review`

## 4. 枚举说明

### 4.1 审核状态 `reviewStatus`

当前接口按数值编码传输：

| 值 | 含义 |
| --- | --- |
| `0` | 草稿 |
| `1` | 待审核 |
| `2` | 审核通过 |
| `3` | 审核拒绝 |

前端请求时推荐直接传数字：

```json
{
  "reviewStatus": 2
}
```

不要传：

```json
{
  "reviewStatus": "APPROVED"
}
```

### 4.2 直播状态 `liveStatus`

当前接口按数值编码传输：

| 值 | 含义 |
| --- | --- |
| `0` | 未开始 |
| `1` | 直播中 |
| `2` | 已结束 |
| `3` | 已取消 |

补充说明：

- 创建直播时一般传 `0`
- 推流成功后后端会自动改成 `1`
- 停止推流后后端会自动改成 `2`
- 审核拒绝时后端会自动改成 `3`

## 5. 封面上传

直播封面不能直接把图片 URL 写进直播保存接口，必须先走统一封面上传。

### 5.1 适用的封面 usage

直播封面固定使用：

```text
live-cover
```

### 5.2 第一步：申请上传地址

- 方法：`POST`
- 路径：`/api/v1/admin/content/files/covers/upload-url`

请求示例：

```json
{
  "usage": "live-cover",
  "originalName": "live-cover.png",
  "contentType": "image/png",
  "fileSize": 37812
}
```

响应示例：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "usage": "live-cover",
    "method": "PUT",
    "uploadUrl": "https://api-test.arez.cc.cd/minio/public/admin/covers/live/2026/06/xxx.png?...",
    "bucketName": "public",
    "objectKey": "admin/covers/live/2026/06/xxx.png",
    "contentType": "image/png",
    "fileSize": 37812,
    "expiresAt": "2026-06-11T21:00:00"
  }
}
```

### 5.3 第二步：直传对象存储

前端直接请求上一步返回的 `uploadUrl`：

- 方法：使用返回的 `method`，当前固定 `PUT`
- 请求体：文件二进制
- Header：`Content-Type` 填原始文件 MIME 类型
- 不要带业务接口的 `Authorization`

### 5.4 第三步：确认上传

- 方法：`POST`
- 路径：`/api/v1/admin/content/files/covers/confirm`

请求示例：

```json
{
  "usage": "live-cover",
  "objectKey": "admin/covers/live/2026/06/xxx.png",
  "originalName": "live-cover.png"
}
```

响应示例：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "fileAssetId": 109,
    "usage": "live-cover",
    "coverUrl": "/api/v1/files/109/content",
    "bucketName": "public",
    "objectKey": "admin/covers/live/2026/06/xxx.png",
    "originalName": "live-cover.png",
    "contentType": "image/png",
    "fileSize": 37812
  }
}
```

说明：

- 直播保存接口里的 `coverUrl`，必须使用这里返回的 `coverUrl`
- 例如：`/api/v1/files/109/content`

## 6. 新建直播

### 6.1 接口信息

- 方法：`POST`
- 路径：`/api/v1/admin/live-sessions`
- 权限：`live:edit`

### 6.2 请求字段说明

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | `string` | 是 | 标题，最长 128 |
| `coverUrl` | `string` | 否 | 封面稳定地址，只能填封面上传确认接口返回值 |
| `anchorName` | `string` | 否 | 主播名称，最长 128 |
| `streamName` | `string` | 否 | 流名称，最长 128，留空时后端自动生成 |
| `speakerName` | `string` | 否 | 展示讲师名称，最长 128 |
| `tags` | `string[]` | 否 | 标签数组，最多 20 个，每个最长 32 |
| `liveUrl` | `string` | 否 | 直播播放地址覆盖值，通常留空 |
| `playbackUrl` | `string` | 否 | 回放地址覆盖值，通常留空 |
| `startAt` | `string(date-time)` | 是 | 开始时间 |
| `endAt` | `string(date-time)` | 否 | 结束时间，必须晚于开始时间 |
| `reviewStatus` | `number` | 是 | 审核状态，见上方枚举 |
| `liveStatus` | `number` | 是 | 直播状态，见上方枚举 |

### 6.3 推荐填写规则

推荐前端默认这样传：

- 新建待审核直播：
  - `reviewStatus = 1`
  - `liveStatus = 0`
- 新建后立即可推流直播：
  - `reviewStatus = 2`
  - `liveStatus = 0`

`liveUrl` 和 `playbackUrl` 通常不要主动填写，留空即可。后端会根据：

- `streamName`
- 直播环境配置

自动生成推流和播放地址。

### 6.4 创建请求示例

```json
{
  "title": "针灸基础直播",
  "coverUrl": "/api/v1/files/109/content",
  "anchorName": "陈景岐",
  "streamName": "live-acupuncture-001",
  "speakerName": "陈景岐",
  "tags": ["针灸", "基础"],
  "liveUrl": null,
  "playbackUrl": null,
  "startAt": "2026-06-11T20:00:00",
  "endAt": "2026-06-11T22:00:00",
  "reviewStatus": 1,
  "liveStatus": 0
}
```

### 6.5 创建响应示例

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "id": 101,
    "title": "针灸基础直播",
    "coverUrl": "/api/v1/files/109/content",
    "anchorName": "陈景岐",
    "streamName": "live-acupuncture-001",
    "speakerName": "陈景岐",
    "tags": ["针灸", "基础"],
    "liveUrl": null,
    "playbackUrl": null,
    "startAt": "2026-06-11T20:00:00",
    "endAt": "2026-06-11T22:00:00",
    "reviewStatus": 1,
    "liveStatus": 0,
    "videos": []
  }
}
```

### 6.6 前端表单默认值建议

推荐：

```json
{
  "title": "",
  "coverUrl": "",
  "anchorName": "",
  "streamName": "",
  "speakerName": "",
  "tags": [],
  "liveUrl": "",
  "playbackUrl": "",
  "startAt": "",
  "endAt": "",
  "reviewStatus": 1,
  "liveStatus": 0
}
```

说明：

- `streamName` 允许留空
- `anchorName` 和 `speakerName` 至少填一个更合理
- 当前后端会做互补：
  - `anchorName` 空时，回退 `speakerName`
  - `speakerName` 空时，回退 `anchorName`

## 7. 修改直播

### 7.1 接口信息

- 方法：`PUT`
- 路径：`/api/v1/admin/live-sessions/{id}`
- 权限：`live:edit`

### 7.2 修改规则

- 请求体字段和“新建直播”完全一致
- 如果本次没有更换封面，继续传原有 `coverUrl`
- 如果本次没有自定义 `streamName`，继续传原值，或者保持为空后让后端沿用现有值
- `endAt` 仍然必须晚于 `startAt`

### 7.3 修改请求示例

```json
{
  "title": "针灸基础直播（更新）",
  "coverUrl": "/api/v1/files/109/content",
  "anchorName": "陈景岐",
  "streamName": "live-acupuncture-001",
  "speakerName": "陈景岐",
  "tags": ["针灸", "基础", "实操"],
  "liveUrl": null,
  "playbackUrl": null,
  "startAt": "2026-06-11T20:30:00",
  "endAt": "2026-06-11T22:30:00",
  "reviewStatus": 1,
  "liveStatus": 0
}
```

## 8. 审核直播

### 8.1 接口信息

- 方法：`PATCH`
- 路径：`/api/v1/admin/live-sessions/{id}/review`
- 权限：`live:review`

### 8.2 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `reviewStatus` | `number` | 是 | 审核状态，只允许传审核状态枚举值 |
| `comment` | `string` | 否 | 审核意见，最长 512 |

### 8.3 审核通过示例

```json
{
  "reviewStatus": 2,
  "comment": "审核通过"
}
```

### 8.4 审核拒绝示例

```json
{
  "reviewStatus": 3,
  "comment": "封面或时间信息不完整"
}
```

### 8.5 审核状态联动规则

- 审核通过：只修改 `reviewStatus`
- 审核拒绝：后端会自动把 `liveStatus` 改成 `3`，即“已取消”

前端需要注意：

- 被拒绝的直播不应再进入推流流程
- 审核通过后，前端才能展示“获取推流配置”或“开始直播引导”

## 9. 获取 OBS 推流配置

### 9.1 接口信息

- 方法：`GET`
- 路径：`/api/v1/admin/live-sessions/{id}/streaming`
- 权限：`live:view`

### 9.2 响应示例

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "id": 101,
    "streamName": "live-acupuncture-001",
    "publishUrl": "rtmp://api-test.arez.cc.cd:1935/live/live-acupuncture-001",
    "httpFlvUrl": "https://api-test.arez.cc.cd/live/live-acupuncture-001.flv",
    "hlsUrl": "https://api-test.arez.cc.cd/live/live-acupuncture-001.m3u8",
    "callbackUrl": "http://app:8080/api/v1/integrations/srs/live-hooks?token=xxx",
    "liveUrl": "https://api-test.arez.cc.cd/live/live-acupuncture-001.flv",
    "playbackUrl": "https://api-test.arez.cc.cd/live/live-acupuncture-001.m3u8",
    "reviewStatus": 2,
    "liveStatus": 0
  }
}
```

### 9.3 前端如何展示给运营和主播

推荐页面直接展示：

- 推流地址：`publishUrl`
- 流名称：`streamName`
- FLV 地址：`httpFlvUrl`
- HLS 地址：`hlsUrl`

OBS 填写规则：

- 服务器：`publishUrl` 去掉最后一段 `/{streamName}`
- 推流密钥：`streamName`

示意：

```text
publishUrl = rtmp://api-test.arez.cc.cd:1935/live/live-acupuncture-001

OBS 服务器 = rtmp://api-test.arez.cc.cd:1935/live
OBS 推流密钥 = live-acupuncture-001
```

## 10. 查询列表与详情

### 10.1 分页查询直播列表

- 方法：`GET`
- 路径：`/api/v1/admin/live-sessions`

查询参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page` | `number` | 否 | 默认 `1` |
| `size` | `number` | 否 | 默认 `20`，最大 `100` |
| `keyword` | `string` | 否 | 按标题、主播、讲师模糊搜索 |
| `reviewStatus` | `number` | 否 | 按审核状态过滤 |
| `liveStatus` | `number` | 否 | 按直播状态过滤 |

请求示例：

```text
GET /api/v1/admin/live-sessions?page=1&size=20&reviewStatus=2&liveStatus=1
```

### 10.2 查询直播详情

- 方法：`GET`
- 路径：`/api/v1/admin/live-sessions/{id}`

说明：

- 详情返回会包含 `videos`
- 适合编辑页回填
- 适合详情页做状态轮询

## 11. 状态轮询建议

如果前端页面需要在“等待主播开始推流”期间自动刷新状态，推荐轮询直播详情接口：

- 轮询接口：`GET /api/v1/admin/live-sessions/{id}`
- 轮询频率：`5s` 或 `10s`

重点关注：

- `reviewStatus`
- `liveStatus`

前端可按下面逻辑展示：

| `reviewStatus` | `liveStatus` | 前端文案建议 |
| --- | --- | --- |
| `1` | `0` | 待审核 |
| `2` | `0` | 待开播 |
| `2` | `1` | 直播中 |
| `2` | `2` | 已结束 |
| `3` | `3` | 已取消 |

## 12. 回放视频管理

直播主记录和回放视频是两套接口，不要混在一个保存请求里。

### 12.1 分页查询回放视频

- 方法：`GET`
- 路径：`/api/v1/admin/live-sessions/{liveSessionId}/videos`

### 12.2 新增回放视频

- 方法：`POST`
- 路径：`/api/v1/admin/live-sessions/videos`
- 权限：`live:edit`

请求字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `liveSessionId` | `number` | 是 | 所属直播 ID |
| `title` | `string` | 是 | 标题，最长 128 |
| `videoUrl` | `string` | 是 | 视频地址，最长 1024 |
| `durationSeconds` | `number` | 否 | 时长秒数 |
| `sortOrder` | `number` | 否 | 排序值，默认 `0` |
| `status` | `number` | 是 | 启用状态 |

新增请求示例：

```json
{
  "liveSessionId": 101,
  "title": "针灸基础直播回放",
  "videoUrl": "https://cdn.example.com/replay/live-acupuncture-001.mp4",
  "durationSeconds": 7200,
  "sortOrder": 1,
  "status": 1
}
```

说明：

- `status` 建议前端按启用状态编码传值，通常 `1` 表示启用
- 当前直播视频没有独立封面字段

### 12.3 修改回放视频

- 方法：`PUT`
- 路径：`/api/v1/admin/live-sessions/videos/{id}`

### 12.4 删除回放视频

- 方法：`DELETE`
- 路径：`/api/v1/admin/live-sessions/videos/{id}`

## 13. 删除直播

### 13.1 单个删除

- 方法：`DELETE`
- 路径：`/api/v1/admin/live-sessions/{id}`

说明：

- 删除直播时，后端会级联删除该直播下的回放视频和标签关联

### 13.2 批量删除

- 方法：`POST`
- 路径：`/api/v1/admin/live-sessions/batch-delete`

请求示例：

```json
{
  "ids": [101, 102, 103]
}
```

## 14. 推荐的前端页面流程

### 14.1 新建页

推荐流程：

1. 用户填写标题、主播、讲师、开始结束时间、标签
2. 用户上传封面，拿到稳定 `coverUrl`
3. 前端提交创建接口
4. 创建成功后跳转详情页或编辑页

### 14.2 审核页

推荐流程：

1. 读取详情
2. 展示基础信息、封面、时间、标签
3. 操作“通过”或“拒绝”
4. 审核成功后刷新详情

### 14.3 推流配置页

推荐流程：

1. 直播必须已审核通过
2. 调用 `/streaming` 接口
3. 展示：
   - OBS 服务器地址
   - 推流密钥
   - FLV 播放地址
   - HLS 播放地址
4. 定时轮询详情接口，等待 `liveStatus` 变为 `1`

## 15. 一套完整接口调用顺序

### 场景一：待审核直播

```text
POST /api/v1/auth/login
  ->
POST /api/v1/admin/content/files/covers/upload-url
  ->
PUT uploadUrl
  ->
POST /api/v1/admin/content/files/covers/confirm
  ->
POST /api/v1/admin/live-sessions
  ->
GET /api/v1/admin/live-sessions/{id}
  ->
PATCH /api/v1/admin/live-sessions/{id}/review
  ->
GET /api/v1/admin/live-sessions/{id}/streaming
```

### 场景二：创建后直接可推流

```text
POST /api/v1/auth/login
  ->
POST /api/v1/admin/content/files/covers/upload-url
  ->
PUT uploadUrl
  ->
POST /api/v1/admin/content/files/covers/confirm
  ->
POST /api/v1/admin/live-sessions
  ->
GET /api/v1/admin/live-sessions/{id}/streaming
```

## 16. 常见错误

### 16.1 `coverUrl must be generated through cover upload APIs`

原因：

- `coverUrl` 填了外链
- `coverUrl` 填了临时签名 URL
- `coverUrl` 不是 `/api/v1/files/{id}/content`

处理：

- 必须先走封面上传确认接口，再把返回值回填到直播请求体

### 16.2 `Stream name already exists`

原因：

- `streamName` 与已有直播重复

处理：

- 更换为新的唯一流名称
- 或者创建时留空，让后端自动生成

### 16.3 `Live end time must be after start time`

原因：

- `endAt` 早于或等于 `startAt`

处理：

- 前端提交前先做时间校验

### 16.4 直播审核通过了，但推流后状态没变

先查这几项：

- 该直播的 `reviewStatus` 是否真的是 `2`
- `streamName` 是否与 OBS 推流密钥一致
- 是否拿的是当前直播的 `/streaming` 配置
- 后端页面是否在轮询详情接口

## 17. 前端实现建议

- 枚举不要写死中文，建议维护本地映射表。
- 创建和编辑页共用一套表单结构。
- 推流配置页和详情页分开做，避免表单和轮询逻辑耦合。
- 如果编辑页允许改 `streamName`，要明确提醒“改流名称会影响 OBS 推流配置和现有播放地址”。
- `liveUrl` 和 `playbackUrl` 默认作为高级字段隐藏；普通运营通常不需要手填。
