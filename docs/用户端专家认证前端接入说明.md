# 用户端专家认证前端接入说明

## 1. 适用范围

本文档用于说明用户端“申请成为专家”页面的前端接入方式。

当前后端已提供完整闭环：

1. 用户端提交专家认证申请
2. 用户端查询当前专家认证状态
3. 管理端审核专家认证
4. 审核通过后自动生成或同步专家档案，并激活用户 `EXPERT` 身份

说明：

- 专家认证是独立业务，不复用学员认证接口。
- 审核通过不等于立刻进入专家工作台。
- 后端会先激活 `EXPERT` 身份，但默认仍保持 `consultEnabled=DISABLED`；只有后台继续开启“可接诊”后，用户端专家工作台接口才可用。

## 2. 接口总览

前置条件：

- 需要先完成用户端登录。
- 需要在后续请求头中带 `Authorization: Bearer <accessToken>`。

### 2.1 提交专家认证申请

- 方法：`POST`
- 路径：`/api/v1/app/experts/certification`
- 认证：需要用户端 `Bearer Token`
- Content-Type：`application/json`

### 2.2 查询当前专家认证状态

- 方法：`GET`
- 路径：`/api/v1/app/experts/certification`
- 认证：需要用户端 `Bearer Token`

### 2.3 查询当前登录用户

- 方法：`GET`
- 路径：`/api/v1/app/auth/me`
- 认证：需要用户端 `Bearer Token`

用途：

- 用于在审核通过后确认 `identities` 是否已出现 `EXPERT`
- 用于确认 `expertMode.enabled` 是否已经切换为可进入专家工作台

## 3. 前端接入流程

### 3.1 流程图

```text
用户登录
  ->
填写专家认证资料
  ->
POST /api/v1/app/experts/certification
  ->
提交成功，状态变为 PENDING
  ->
GET /api/v1/app/experts/certification
  ->
轮询或页面刷新查看审核状态

如果 REJECTED
  ->
展示 rejectReason
  ->
允许用户修改后重新提交

如果 APPROVED
  ->
GET /api/v1/app/auth/me
  ->
identities 包含 EXPERT
  ->
若 expertMode.enabled=false
     显示“已认证，待后台开启接诊”
若 expertMode.enabled=true
     允许进入专家工作台
```

### 3.2 推荐页面状态

```text
[未提交]
  显示申请表单

[审核中 PENDING]
  显示已提交资料
  显示“审核中”
  禁止重复点击“新增申请”，但允许继续提交覆盖资料

[已驳回 REJECTED]
  显示驳回原因
  允许修改资料后重新提交

[已通过 APPROVED]
  显示“已认证专家”
  如果 expertMode.enabled=false：
    显示“后台尚未开启接诊”
  如果 expertMode.enabled=true：
    显示“进入专家工作台”
```

## 4. 提交申请接口

### 4.1 请求体字段

请求示例：

```json
{
  "realName": "张三",
  "gender": 1,
  "birthDate": "1988-06-18",
  "mobile": "13900000001",
  "title": "主任医师",
  "organization": "广州中医药大学第一附属医院",
  "organizationId": 3,
  "practiceTypeId": 2,
  "specialty": "中医内科、治未病",
  "introduction": "长期从事中医内科与慢病调理。",
  "consultationNotice": "工作日 18:00 前回复，急症请线下就医。",
  "categoryIds": [11, 12],
  "certificationFiles": [
    {
      "fileAssetId": 208,
      "materialType": "doctor_certificate",
      "sortOrder": 0
    },
    {
      "sourceUrl": "https://example.com/materials/title-proof.jpg",
      "materialType": "title_certificate",
      "sortOrder": 1
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `realName` | `string` | 是 | 真实姓名，最长 64 字符 |
| `gender` | `number` | 否 | 性别：`0=UNKNOWN`、`1=MALE`、`2=FEMALE` |
| `birthDate` | `string` | 否 | 出生日期，格式 `yyyy-MM-dd` |
| `mobile` | `string` | 否 | 联系电话，最长 32 字符 |
| `title` | `string` | 否 | 职称，最长 128 字符 |
| `organization` | `string` | 否 | 所属机构名称，最长 128 字符 |
| `organizationId` | `number` | 否 | 所属机构 ID |
| `practiceTypeId` | `number` | 否 | 执业类型 ID |
| `specialty` | `string` | 否 | 擅长方向，最长 255 字符 |
| `introduction` | `string` | 否 | 专家简介 |
| `consultationNotice` | `string` | 否 | 咨询须知，最长 512 字符 |
| `categoryIds` | `number[]` | 是 | 专家分类 ID 列表，至少 1 个 |
| `certificationFiles` | `array` | 否 | 认证材料列表 |

`certificationFiles` 子项字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `fileAssetId` | `number` | 否 | 已上传文件资产 ID |
| `sourceUrl` | `string` | 否 | 外部材料地址 |
| `materialType` | `string` | 否 | 材料类型标识，最长 64 字符 |
| `sortOrder` | `number` | 否 | 排序值 |

材料规则：

- `fileAssetId` 和 `sourceUrl` 二选一，至少传一个。
- 当前接口不提供专家专用上传能力。
- 如果前端已有稳定文件资产，优先传 `fileAssetId`。
- 如果当前页面还未接对象存储材料上传，可暂时传 `sourceUrl`。

### 4.2 成功响应

响应示例：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "id": 5,
    "userId": 1003,
    "realName": "张三",
    "gender": 1,
    "birthDate": "1988-06-18",
    "mobile": "13900000001",
    "title": "主任医师",
    "organization": "广州中医药大学第一附属医院",
    "organizationId": 3,
    "practiceTypeId": 2,
    "specialty": "中医内科、治未病",
    "introduction": "长期从事中医内科与慢病调理。",
    "consultationNotice": "工作日 18:00 前回复，急症请线下就医。",
    "categoryIds": [11, 12],
    "certificationStatus": 1,
    "certificationSubmittedAt": "2026-06-12T11:20:31",
    "certificationReviewedAt": null,
    "certificationReviewedBy": null,
    "rejectReason": null,
    "certificationFiles": [
      {
        "id": 21,
        "fileAssetId": 208,
        "sourceUrl": null,
        "materialType": "doctor_certificate",
        "sortOrder": 0
      }
    ]
  }
}
```

状态值说明：

| 值 | 含义 |
| --- | --- |
| `0` | `UNSUBMITTED` 未提交 |
| `1` | `PENDING` 审核中 |
| `2` | `APPROVED` 已通过 |
| `3` | `REJECTED` 已驳回 |

### 4.3 提交规则

- 当前用户还没有申请记录时，会新建一条申请。
- 当前用户已有申请记录且状态为 `PENDING` 或 `REJECTED` 时，允许重复提交。
- 重复提交会覆盖原申请资料、替换分类和材料，并把状态重置为 `PENDING`。
- 当前用户申请已 `APPROVED` 时，禁止重复提交。

已通过后再次提交失败示例：

```json
{
  "success": false,
  "code": "CONFLICT",
  "message": "Expert certification is already approved",
  "data": null
}
```

### 4.4 常见失败场景

1. 未登录

```json
{
  "success": false,
  "code": "UNAUTHORIZED",
  "message": "Unauthorized"
}
```

2. `categoryIds` 为空

```json
{
  "success": false,
  "code": "VALIDATION_ERROR",
  "message": "Request validation failed"
}
```

3. 分类不存在或已禁用

```json
{
  "success": false,
  "code": "BAD_REQUEST",
  "message": "Expert category does not exist"
}
```

4. 材料项既没有 `fileAssetId`，也没有 `sourceUrl`

```json
{
  "success": false,
  "code": "BAD_REQUEST",
  "message": "Certification file requires fileAssetId or sourceUrl"
}
```

## 6. 与 `/api/v1/app/auth/me` 的联动

审核通过后，建议前端再调用一次：

```http
GET /api/v1/app/auth/me
Authorization: Bearer <accessToken>
```

重点关注两个字段：

| 字段 | 说明 |
| --- | --- |
| `identities` | 审核通过后会包含 `EXPERT` |
| `expertMode` | 只有当专家档案启用且 `consultEnabled=ENABLED` 时，`enabled` 才会变成 `true` |

审核通过但还未开启接诊时，典型响应片段：

```json
{
  "data": {
    "identities": ["EXPERT"],
    "expertMode": {
      "enabled": false,
      "expertId": null,
      "realName": null,
      "consultEnabled": false
    }
  }
}
```

这不是异常，表示：

- 用户已经是“认证通过的专家”
- 但后台还没有把该专家设置为可接诊
- 前端此时不要放开专家工作台入口

## 7. 页面实现建议

### 7.1 表单建议字段

- 真实姓名
- 性别
- 出生日期
- 联系电话
- 职称
- 所属机构
- 执业类型
- 擅长方向
- 专家简介
- 咨询须知
- 专家分类
- 认证材料

### 7.2 前端状态提示文案建议

| 状态 | 建议文案 |
| --- | --- |
| 未提交 | `提交专家认证后，后台审核通过即可获得专家身份。` |
| 审核中 | `专家认证审核中，请耐心等待。` |
| 已驳回 | `专家认证未通过：{rejectReason}` |
| 已通过但未接诊 | `已通过专家认证，待后台开启接诊后可进入专家工作台。` |
| 已通过且可接诊 | `已认证并已开启接诊，可进入专家工作台。` |

## 8. 联调检查清单

- 能正常获取用户端 `accessToken`
- 未登录访问专家认证接口时返回 `401`
- 首次提交后状态变为 `PENDING`
- 审核驳回后能看到 `rejectReason`
- 驳回后重新提交会重新进入 `PENDING`
- 审核通过后 `GET /api/v1/app/auth/me` 的 `identities` 包含 `EXPERT`
- 审核通过但未开启接诊时，前端不放开专家工作台入口
- 后台开启接诊后，`expertMode.enabled=true`，专家工作台入口恢复
