# 用户端微信扫码登录前端接入说明

## 1. 适用范围

本文档用于说明用户端 PC 官网微信扫码登录的前端接入方式。

当前项目分两个阶段：

1. 开发阶段：先走后端 mock 的扫码登录链路，不依赖真实微信网站应用。
2. 上线阶段：产品官网上线并申请通过微信开放平台网站应用后，切回真实微信扫码登录。

当前仓库默认优先支持第 1 阶段。

## 2. 当前实现概览

后端已提供以下能力：

- 获取官网微信扫码配置：`GET /api/v1/app/auth/wechat-web/qr-config`
- 提交扫码登录结果：`POST /api/v1/app/auth/wechat-web/login`
- 首次登录绑定手机号：`POST /api/v1/app/auth/wechat-bind-mobile`

当前开发阶段的关键约定：

- 当后端配置 `WECHAT_WEB_MOCK_ENABLED=true` 时：
  - 前端不需要真的展示微信二维码。
  - 前端也不需要真实的微信开放平台 `AppID / AppSecret / 回调地址`。
  - 前端只需要走“获取 state -> 提交 mock code -> 按需绑定手机号”这条链路。

## 3. 接口总览

### 3.1 获取扫码配置

- 方法：`GET`
- 路径：`/api/v1/app/auth/wechat-web/qr-config`
- 认证：不需要

### 3.2 提交扫码登录

- 方法：`POST`
- 路径：`/api/v1/app/auth/wechat-web/login`
- 认证：不需要
- Content-Type：`application/json`

### 3.3 绑定手机号

- 方法：`POST`
- 路径：`/api/v1/app/auth/wechat-bind-mobile`
- 认证：不需要
- Content-Type：`application/json`

### 3.4 获取当前登录用户

- 方法：`GET`
- 路径：`/api/v1/app/auth/me`
- 认证：需要 `Authorization: Bearer <token>`

## 4. 开发阶段前端接入流程

### 4.1 流程图

```text
点击“模拟微信扫码登录”
  ->
GET /api/v1/app/auth/wechat-web/qr-config
  ->
拿到 state
  ->
POST /api/v1/app/auth/wechat-web/login
  ->
如果 needBindMobile=false
  -> 保存 accessToken
  -> 调 /api/v1/app/auth/me 或进入站内

如果 needBindMobile=true
  -> 跳转手机号绑定页
  -> POST /api/v1/app/auth/wechat-bind-mobile
  -> 保存 accessToken
  -> 进入站内
```

### 4.2 步骤 1：获取扫码配置

请求：

```http
GET /api/v1/app/auth/wechat-web/qr-config
```

响应示例：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "appId": "mock-wechat-web-appid",
    "redirectUri": "http://127.0.0.1/mock/wechat/callback",
    "scope": "snsapi_login",
    "state": "4d89a2af5b1f4b2d8d8f8b0cbe7b0c1f",
    "expiresIn": 600
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `appId` | `string` | 当前开发阶段可能是后端返回的占位值 |
| `redirectUri` | `string` | 当前开发阶段可能是后端返回的占位值 |
| `scope` | `string` | 当前固定为 `snsapi_login` |
| `state` | `string` | 本次登录防重放、防伪造状态值 |
| `expiresIn` | `number` | `state` 过期秒数 |

说明：

- 当前开发阶段里，前端最关键的是拿到 `state`。
- `appId` 和 `redirectUri` 在 mock 阶段仅用于占位展示，不要求前端真正跳微信。

### 4.3 步骤 2：提交 mock 扫码登录

开发阶段前端可直接构造一个固定 `code`，例如：

- `dev-web-user-01`
- `dev-web-user-02`
- `dev-web-user-03`

请求示例：

```json
{
  "code": "dev-web-user-01",
  "state": "4d89a2af5b1f4b2d8d8f8b0cbe7b0c1f"
}
```

接口：

```http
POST /api/v1/app/auth/wechat-web/login
Content-Type: application/json
```

#### 场景 A：已注册用户，直接登录

响应示例：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "registered": true,
    "needBindMobile": false,
    "bindToken": null,
    "tokenType": "Bearer",
    "accessToken": "xxxxxxxx",
    "expiresIn": 7200,
    "user": {
      "id": 1001,
      "username": "u13900000001",
      "nickname": "wxweb_user-01",
      "avatarUrl": null,
      "lastLoginAt": "2026-06-01T14:30:00"
    }
  }
}
```

前端处理：

1. 保存 `tokenType` 和 `accessToken`
2. 后续请求带 `Authorization: Bearer <accessToken>`
3. 跳转到登录后页面

#### 场景 B：新用户，需要绑定手机号

响应示例：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "registered": false,
    "needBindMobile": true,
    "bindToken": "xxxxxxxx",
    "tokenType": null,
    "accessToken": null,
    "expiresIn": 600,
    "user": null
  }
}
```

前端处理：

1. 保存 `bindToken`
2. 跳转手机号绑定页
3. 收集手机号和验证码后调用绑定接口

### 4.4 步骤 3：绑定手机号

请求示例：

```json
{
  "bindToken": "xxxxxxxx",
  "mobile": "13900000011",
  "code": "123456"
}
```

接口：

```http
POST /api/v1/app/auth/wechat-bind-mobile
Content-Type: application/json
```

响应示例：

```json
{
  "success": true,
  "code": "OK",
  "message": "success",
  "data": {
    "tokenType": "Bearer",
    "accessToken": "xxxxxxxx",
    "expiresIn": 7200,
    "user": {
      "id": 1002,
      "username": "u13900000011",
      "nickname": "wxweb_user-01",
      "avatarUrl": null,
      "lastLoginAt": "2026-06-01T14:35:00"
    }
  }
}
```

说明：

- 如果后端同时开启了短信 mock，则验证码直接使用后端配置的 mock 值。
- 当前本地开发环境通常为：

```env
APP_USER_AUTH_SMS_MOCK_ENABLED=true
APP_USER_AUTH_SMS_MOCK_CODE=123456
```

## 5. mock 机制说明

当前开发阶段，后端对 `code` 的处理规则是：

```text
openId  = mock-web-openid-{code}
unionId = mock-unionid-{code}
```

这意味着：

- 同一个 `code` 会稳定映射到同一个 mock 微信身份。
- 第一次使用某个 `code` 时，通常会进入绑定手机号流程。
- 同一个 `code` 绑定成功后，再次使用这个 `code` 登录，应直接命中已绑定用户。

推荐约定：

| 用途 | code |
| --- | --- |
| 开发账号 1 | `dev-web-user-01` |
| 开发账号 2 | `dev-web-user-02` |
| 开发账号 3 | `dev-web-user-03` |

## 6. 前端页面建议

### 6.1 开发阶段页面建议

开发环境建议不要展示真实二维码，而是直接显示一个 mock 登录入口：

```text
[ 微信扫码登录 ]

开发环境：
[ 模拟微信扫码登录 ]
```

建议交互：

1. 点击“模拟微信扫码登录”
2. 内部先调 `qr-config`
3. 再自动调 `wechat-web/login`
4. 如果返回 `needBindMobile=true`，跳绑定页
5. 否则直接登录

### 6.2 真实上线前预留的页面结构

后期切回真实微信扫码时，可切换为：

```text
[ 微信扫码登录 ]
┌────────────────────┐
│   微信登录二维码区  │
└────────────────────┘

扫码后：
-> 前端回调页拿到 code + state
-> 调 /api/v1/app/auth/wechat-web/login
```

## 7. 前端实现示例

以下示例使用 `axios`。

### 7.1 获取扫码配置

```ts
import axios from "axios";

export async function getWechatWebQrConfig() {
  const response = await axios.get("/api/v1/app/auth/wechat-web/qr-config");
  return response.data.data;
}
```

### 7.2 提交 mock 扫码登录

```ts
export async function loginByMockWechatWeb(code: string, state: string) {
  const response = await axios.post("/api/v1/app/auth/wechat-web/login", {
    code,
    state,
  });
  return response.data.data;
}
```

### 7.3 绑定手机号

```ts
export async function bindWechatMobile(
  bindToken: string,
  mobile: string,
  code: string
) {
  const response = await axios.post("/api/v1/app/auth/wechat-bind-mobile", {
    bindToken,
    mobile,
    code,
  });
  return response.data.data;
}
```

### 7.4 开发阶段一键 mock 登录示例

```ts
export async function mockWechatScanLogin() {
  const qrConfig = await getWechatWebQrConfig();

  const loginResult = await loginByMockWechatWeb(
    "dev-web-user-01",
    qrConfig.state
  );

  if (loginResult.needBindMobile) {
    return {
      needBindMobile: true,
      bindToken: loginResult.bindToken,
    };
  }

  localStorage.setItem("app_access_token", loginResult.accessToken);
  return {
    needBindMobile: false,
    accessToken: loginResult.accessToken,
    user: loginResult.user,
  };
}
```

## 8. 切回真实微信扫码时前端要改什么

产品官网上线并申请通过微信开放平台网站应用后，需要切回真实扫码登录。前端需要调整以下内容：

1. 不再使用固定 mock `code`
2. 登录页接入微信官方 `wxLogin.js` 或者跳转 `qrconnect`
3. 回调页从 URL 中读取真实 `code` 和 `state`
4. 再调用 `POST /api/v1/app/auth/wechat-web/login`

后端需同时满足：

- `WECHAT_WEB_MOCK_ENABLED=false`
- 配置真实 `WECHAT_WEB_APP_ID`
- 配置真实 `WECHAT_WEB_APP_SECRET`
- 配置真实 `WECHAT_WEB_REDIRECT_URI`

前端建议保留一个环境开关：

```ts
const useMockWechatWebLogin =
  import.meta.env.VITE_WECHAT_WEB_MOCK === "true";
```

处理方式：

- `true`：显示“模拟微信扫码登录”
- `false`：显示真实二维码登录

## 9. 注意事项

### 9.1 `state` 只能用一次

- `qr-config` 返回的 `state` 用过一次后就会失效。
- 不要缓存很久后重复提交。

### 9.2 mock `code` 要稳定

- 如果你希望复用同一个测试用户，请固定使用同一个 `code`。
- 如果想模拟新用户，请换一个新的 `code`。

### 9.3 绑定手机号成功后，要保存 token

- 真正的登录态来自绑定接口或登录成功接口返回的 `accessToken`。
- `bindToken` 只是临时绑定凭证，不能当登录 token 使用。

### 9.4 当前 mock 不代表真实微信 UI

当前开发阶段只验证后端登录链路：

- 能测注册 / 登录 / 绑定手机号 / token 签发
- 不能代表真实微信二维码展示、扫码确认、官方回调页行为

## 10. 推荐联调顺序

推荐前端按这个顺序联调：

1. 先打通 `模拟微信扫码登录 -> 需要绑定手机号`
2. 再打通 `绑定手机号 -> 登录成功`
3. 再验证 `同一个 code 二次登录 -> 直接登录`
4. 最后在产品官网上线后再切到真实微信扫码
